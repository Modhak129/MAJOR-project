# DEMO VIDEO LIFECYCLE FIX

## Root causes found

1. **State Disconnect:** The React frontend blindly set `demoState = "playing"` immediately after sending the start HTTP request, regardless of whether the edge node actually started inference.
2. **Replay Failure (OpenCV EOF):** Replay attempted to use `cv2.VideoCapture.set(cv2.CAP_PROP_POS_FRAMES, 0)` on a stream that had already hit EOF. OpenCV is notoriously unreliable with this operation on certain formats, resulting in a frozen capture.
3. **Ghost Workers & Model Switching:** Changing the selected model (Edge Node 1 vs Edge Node 2) in the UI did not explicitly stop the old node's video loop. Both nodes could end up fighting over the Socket.IO namespace or silently running in the background.
4. **Stale Events:** Late `demo_finished` events from old demo runs could instantly terminate new runs, and the `AlertManager` preserved old PPE tracking histories across Replays.

## Backend changes

Files: `edge/fl_client.py`, `edge/inference.py`
Functions: `on_edge_control`, `run_background_inference_loop`, `reset_tracker`
Changes:
- Replaced `cv2.CAP_PROP_POS_FRAMES` with robust complete `demo_cap.release()` and reinstantiation upon Replay.
- Introduced a `demo_session_id` to `edge/fl_client.py`.
- Emits explicit `demo_started` (on first successful frame) and `demo_error` (if file fails to open).
- `inference.py` now resets the `alert_manager.history` when `reset_tracker()` is called, preventing old alert cooldowns from suppressing alerts in a replayed video.

## Frontend changes

Files: `dashboard/frontend-react/src/pages/LiveMonitoring.jsx`
Components: `LiveMonitoring`
State changes:
- `demoState` is now driven entirely by definitive Socket.IO events (`demo_started`, `demo_finished`, `demo_error`) accompanied by strict `session_id` matching.
- Implemented a `starting` state which displays a distinct loading indicator ("Starting Edge inference...") while waiting for the first frame.

## Replay fix

How replay now works: Clicking Replay generates a completely new `session_id`. It sends this to the backend, which explicitly releases the old OpenCV `VideoCapture` object, destroys the ByteTrack state, clears the PPE alert history, re-opens the file from scratch, and emits a new `demo_started` event when the first frame is processed. 

## Model-switch fix

How model switching now works: A new `handleModelChange` function detects if a video is currently loaded. If so, it explicitly sends a shutdown command (`source_type: "webcam"`) to the *old* model's edge node. It then generates a new `session_id` and starts the video loop seamlessly on the *new* model's edge node.

## Session management

Session ID: A UUID (`crypto.randomUUID()`) is generated by React on every Start, Replay, or Model Switch.
How stale events are prevented: React tracks the current `demoSessionId`. Any incoming `processed_frame_result`, `demo_finished`, or `demo_started` event containing an older or mismatched `session_id` is immediately discarded. 

## Pause/resume

Implementation: Pausing changes the backend `demo_playback_state` to `"paused"`. The `while True` inference loop spins gently with a `time.sleep(0.1)` without advancing the OpenCV capture, preserving the exact frame position. Resuming changes the state back to `"playing"`.

## EOF handling

Implementation: When `demo_cap.read()` returns `False` (EOF), the backend actively calls `demo_cap.release()`, emits `demo_finished` with the session ID, and safely awaits further instructions.
